# CS 350: Emerging Systems Architectures and Technologies

## Project Overview

For this course, I completed two projects that helped me understand how software interacts with hardware components. The first project was a Raspberry Pi thermostat, and the second was a UART LED control system. Both projects gave me experience with Python programming, embedded systems, hardware communication, and troubleshooting.

### Raspberry Pi Thermostat

The thermostat project involved developing an embedded system that monitors temperature and responds to user input. I used a Raspberry Pi, a temperature sensor, an LCD, LEDs, and buttons to build a thermostat that could operate in off, heat, and cool modes. The program displayed temperature information and allowed the target temperature to be adjusted. This project helped me understand how hardware components and software work together to create a functional system.

### UART LED Control

The UART LED control project involved creating a client and server program that communicated through a serial connection to control an LED. The system accepted commands to turn the LED on or off and provided a command to exit the program. This project helped me learn more about serial communication, hardware configuration, and the relationship between software commands and physical hardware responses.

## Reflection

### What did you do particularly well?

I think I did particularly well at troubleshooting and working through problems when the hardware and software did not work as expected. I learned to check connections, review my code, and test different parts of the system to find the source of problems. I also gained experience working with hardware components that I had not used much before. These projects helped me become more comfortable learning new technologies and applying what I learned to complete a working system.

### Where could you improve?

One area where I could improve is planning and testing each part of a project earlier in the development process. Testing individual components before combining everything would make it easier to identify problems. I could also improve my documentation by explaining hardware connections and recording troubleshooting steps as I work. In future projects, I want to spend more time reviewing hardware specifications and planning how the components will work together before beginning implementation.

### What tools and/or resources are you adding to your support network?

I am adding the Raspberry Pi documentation, Python documentation, hardware datasheets, wiring diagrams, and serial communication resources to my support network. I also found that using a terminal, a code editor, and diagramming tools such as draw.io helped me develop and document my projects. When troubleshooting, I learned the value of comparing reliable technical resources and breaking problems into smaller steps. These resources will help me continue learning and solve problems more independently in future projects.

### What skills from this project will be particularly transferable to other projects and/or course work?

The skills I developed include Python programming, debugging, hardware and software integration, serial communication, and state-machine design. These skills can be used in other embedded systems projects, automation, Internet of Things devices, and applications that interact with external hardware. I also learned to consider hardware limitations and communication requirements when designing software. Understanding how these factors affect a system will help me make better decisions in future computer science courses and software development projects.

### How did you make this project maintainable, readable, and adaptable?

I worked to keep my code organized and use clear control logic to manage how each system operated. In the UART project, the client and server programs had separate responsibilities, which made the communication process easier to understand. In the thermostat project, the different operating modes helped organize the system's behavior. I also created state-machine documentation to explain how the thermostat transitions between states. These practices make the projects easier to understand, test, and modify. In future projects, I would continue improving maintainability by adding helpful comments, documenting setup instructions, and separating hardware configuration from the main program logic.

## Conclusion

These projects helped me understand how software, hardware architecture, and communication work together in embedded systems. I gained practical experience with hardware integration, debugging, and designing software that responds to real-world inputs. I also learned the importance of planning, testing, and technical documentation. I can apply these skills to future coursework and use this experience as a foundation for more advanced software and hardware projects.
